# Инструкции для AI-агентов UNIPLEX

## Перед началом задачи

- Полностью прочитай актуальный `UNIPLEX_PROJECT_MASTER.md` в текущей рабочей копии. Сверь задачу с описанной архитектурой, текущими приоритетами и ограничениями. Проверяй фактическое поведение по коду и конфигурации.
- Общайся с владельцем проекта на русском языке. В отчёте указывай сделанные изменения, результаты проверок и открытые вопросы. Для изменений, затрагивающих эксплуатацию, отдельно указывай готовность к развёртыванию и факт развёртывания.
- При существенных изменениях архитектуры, схемы данных, контрактов, рабочих процессов или состояния проекта обновляй `UNIPLEX_PROJECT_MASTER.md` в той же задаче. Если владелец ограничил список разрешённых файлов, сообщи, какое обновление паспорта требуется.

## Архитектура и данные

- UNIPLEX автоматизирует работу производственного бизнеса с деловой перепиской и документами. Сохраняй границы модулей импорта почты по IMAP, разбора писем и вложений, извлечения документов, AI-анализа, хранения и поиска.
- PostgreSQL — источник достоверных структурированных данных. Остатки, суммы, количества и финансовые показатели получай из PostgreSQL.
- Qdrant — векторный индекс для семантического поиска по текстам и фрагментам. RAG использует найденный контекст и возвращает ответы со ссылками на источники.
- Для каждого факта сохраняй значение, тип и ключ поля, дату и контекст, версию извлечения, оценку уверенности и статус проверки. Сохраняй связь с письмом, вложением или документом и место в источнике.
- Принимай достоверные и однозначные бизнес-факты автоматически при выполнении установленных критериев качества. Ручная проверка нужна для сомнительных и конфликтующих фактов. Перед перезаписью подтверждённого значения проверь и разреши конфликты и сохрани прежнее значение в истории.

## Разработка и тестирование

- В рамках согласованной задачи самостоятельно анализируй код, реализуй решение, запускай безопасные тесты и исправляй выявленные ошибки. Отдельное разрешение на безопасные промежуточные действия в пределах задачи не требуется.
- Сохраняй совместимость с существующими данными и контрактами. Проверяй затронутые сценарии через штатные точки входа и используй заглушки внешних провайдеров. Не удаляй существующие тестовые базы данных. Для новых интеграционных тестов используй отдельные изолированные базы с синтетическими данными.
- При изменении очередей и воркеров проверяй сохранение атомарности, владение заданием на границе фиксации результата, heartbeat, истечение lease, сбои, восстановление и повторный запуск. Для изменений конкурентного поведения обязательны тесты с параллельными транзакциями. Покажи, что воркер, потерявший lease, не может зафиксировать результат.
- Различай гипотезы по коду, воспроизведённые дефекты и подтверждённые производственные инциденты. Сообщай о выполненных проверках и ошибках тестирования. Заявляй о готовности функционала только после подтверждающих проверок.

## Безопасность и эксплуатация

- Не запрашивай, не открывай, не копируй и не раскрывай секреты, включая файлы `.env`, пароли, приватные ключи и API-токены. Не добавляй в Git рабочие данные, резервные копии и временные файлы.
- Без явного разрешения владельца не подключайся к VPS, не меняй производственную среду, базы данных, конфигурацию и работающие сервисы, не выполняй развёртывание. Перед согласованным изменением схемы проверь состояние миграций и наличие резервной копии.
- Без отдельного явного разрешения владельца не выполняй платные API-запросы.
- Почтовая подсистема работает по IMAP исключительно на чтение выделенного ящика Яндекса (Yandex). Текущая архитектура запрещает отправку, удаление и перемещение писем, а также изменение их флагов.

### Рабочие каталоги

- `C:\UNIPLEX` — локальная среда разработки.
- `/opt/uniplex-git` — отдельная Git-копия на VPS.
- `/opt/uniplex` — действующая производственная система.

## Git

- Перед изменениями проверь текущую ветку, `HEAD` и состояние рабочего дерева. Сохраняй изменения владельца. Перед завершением проверь diff и убедись, что изменены только разрешённые файлы.
- Выполняй `git pull`, `git commit` и `git push` только с разрешения владельца. Для согласованного обновления `main` используй `git pull --ff-only origin main`. Перед согласованным коммитом проверь его состав и сформулируй понятное сообщение.
